# 0004. 일괄 가져오기: 형식과 중복·오류 처리

- 상태: 확정
- 날짜: 2026-10-02

## 결정

컴퓨터에서 만든 JSON 묶음(`docs/sources/FORMAT.md`의 "가져오기 묶음")을 앱 화면의 입력칸에 붙여넣어 지문·문장별 해석·메모·단어를 한 번에 등록한다. 읽기·검증은 `mobile/src/lib/importer/`, 저장은 `mobile/src/db/importer.ts`, 화면은 `mobile/src/app/import.tsx`.

- 오류가 하나라도 있으면 아무것도 등록하지 않고 위치(`N번째 지문`)와 사유를 보여준다.
- 같은 출처(교과서: 책+단원, 학평: 연·월·번호)의 지문이 이미 있으면 건너뛴다. 덮어쓰지 않는다.
- 지문마다 한 트랜잭션이다.
- 학평 연도는 스캔에 없어 변환 도구에서 `--year`를 직접 받는다.

## 이유와 기각한 대안

- 앱에 OCR을 넣지 않기로 한 결정(0001)과 같은 방향이다. 앱은 이미 정리된 데이터를 받기만 한다.
- 입력칸 붙여넣기는 새 의존성이 필요 없다. 기각: 클립보드·문서 선택기(`expo-clipboard`, `expo-document-picker`, 새 의존성이라 승인 필요), 앱 번들에 JSON을 넣는 방식(지문 본문이 공개 저장소에 올라감).
- 덮어쓰기 대신 건너뛰기: 사용자가 앱에서 고친 해석·메모가 다시 가져오기로 사라지지 않게 한다. 다시 가져오려면 그 지문을 먼저 지운다. 기각: 덮어쓰기, 병합(어느 쪽이 맞는지 기계가 알 수 없음).
- 전부 아니면 전무: 일부만 들어간 상태에서 어디까지 들어갔는지 사용자가 알아내야 하는 일을 막는다. 지문별 파일을 쓰면 오류 범위도 작아진다.
- 교과서 지문은 문단(쪽) 단위로 나누어 등록한다. 한 과 전체를 한 지문으로 하면 암기 한 번에 50문장 이상이다. 이 묶는 방식은 가져오기 형식과 무관하고 묶음을 만드는 쪽의 선택이다.

## 한계

- 실제 iPhone에서의 붙여넣기(수십 KB의 JSON을 입력칸에 넣을 때의 속도)는 확인하지 못했다. 웹 빌드에서는 44KB 묶음이 문제없었다.
- 중복 판단은 출처 필드만 본다. 같은 단원 이름으로 내용이 다른 지문은 구분하지 못한다.
